Compilar módulos de kernel fuera de la placa (**cross-compiling**) es la práctica estándar en la industria. Te evita consumir los ciclos de vida de la tarjeta SD de tu Raspberry Pi 5 y aprovecha toda la potencia de tu PC de escritorio.

Dado que la **Raspberry Pi 5** utiliza un procesador Broadcom BCM2712 de 64 bits (arquitectura ARM64 / AArch64) y delega sus GPIOs a un chip coprocesador llamado **RP1**, realizaremos todo el proceso apuntando a dicha arquitectura sin que la Pi ejecute una sola línea de compilación.

---

## Paso 1: Configurar la Máquina Host (Tu PC con Linux)

Primero, debemos instalar las herramientas de compilación, las dependencias de desarrollo del kernel de Linux y, lo más importante, el **toolchain de compilación cruzada para 64 bits (`aarch64-linux-gnu-`)**.

En tu terminal de Linux (asumiendo una distribución basada en Debian/Ubuntu), ejecuta:

```bash
sudo apt update
sudo apt install build-essential bc bison flex libssl-dev libelf-dev libc6-dev libncurses5-dev crossbuild-essential-arm64 git kmod -y

```

---

## Paso 2: Obtener y preparar las fuentes del Kernel de Raspberry Pi

Para compilar un módulo externo (`out-of-tree module`), necesitas obligatoriamente las fuentes estructuradas del kernel exacto que corre en tu Raspberry Pi 5.

1. **Verifica la versión en tu Raspberry Pi:** Entra por SSH a tu Pi y ejecuta `uname -r`. Verás algo como `6.6.x-v8+` o similar.
2. **Descarga el código en tu PC:** Ve a tu máquina Linux y clona la rama correspondiente del repositorio oficial de Raspberry Pi. Si tu versión es la 6.6.y, ejecuta:

```bash
cd ~
git clone --depth=1 --branch rpi-6.6.y https://github.com/raspberrypi/linux.git
cd linux

```

3. **Configurar el entorno para Raspberry Pi 5:**
Definimos las variables de entorno para indicarle al sistema que use el compilador cruzado de 64 bits y la arquitectura de destino. El archivo de configuración por defecto para la Pi 5 es `bcm2712_defconfig`.

```bash
export ARCH=arm64
export CROSS_COMPILE=aarch64-linux-gnu-

# Generar la configuración base para Pi 5
make bcm2712_defconfig

# Preparar scripts y cabeceras necesarias para compilar módulos externos
make modules_prepare

```

---

## Paso 3: Escribir el código del módulo (LKM)

Crea una carpeta independiente en tu PC para tu módulo (por ejemplo, `~/mi_modulo_rpi`) y genera el archivo fuente en C.

```bash
mkdir ~/mi_modulo_rpi && cd ~/mi_modulo_rpi
nano modulo_sensor.c

```

Aquí tienes una plantilla limpia de calidad profesional. Implementa el "Hola Mundo" en el log del sistema y añade el uso del framework de GPIO oficial de Linux.

> ⚠️ **Nota crítica de hardware para Pi 5:** No uses manipulación directa de registros de memoria física para los GPIO en la Pi 5. Debido al nuevo chip **RP1**, debes interactuar exclusivamente mediante la API del Kernel (`<linux/gpio.h>`), la cual abstrae los cambios de hardware transparentemente.

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/gpio.h> // API estándar del Kernel para GPIO

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Tu Nombre");
MODULE_DESCRIPTION("Driver LKM básico de sensado para Raspberry Pi 5 (ARM64)");
MODULE_VERSION("1.0");

#define GPIO_PIN_SENSOR 17 // Cambia al GPIO que quieras usar (ej. GPIO 17)

// Función que se ejecuta al cargar el módulo (insmod)
static int __init modulo_sensor_init(void) {
    int estado_senal;

    printk(KERN_INFO "[RPI5-LKM] Inicializando el módulo de sensado cruzado...\n");

    // Validar si el GPIO está disponible en el sistema
    if (!gpio_is_valid(GPIO_PIN_SENSOR)) {
        printk(KERN_ERR "[RPI5-LKM] Error: El GPIO %d no es válido.\n", GPIO_PIN_SENSOR);
        return -ENODEV;
    }

    // Solicitar el GPIO al Kernel
    if (gpio_request(GPIO_PIN_SENSOR, "rpi5_sensor_pin") < 0) {
        printk(KERN_ERR "[RPI5-LKM] Error: No se pudo reservar el GPIO %d.\n", GPIO_PIN_SENSOR);
        return -1;
    }

    // Configurar el pin como Entrada
    gpio_direction_input(GPIO_PIN_SENSOR);

    // Leer una señal inicial del pin
    estado_senal = gpio_get_value(GPIO_PIN_SENSOR);
    printk(KERN_INFO "[RPI5-LKM] Módulo cargado con éxito. Estado actual del pin %d: %d\n", 
            GPIO_PIN_SENSOR, estado_senal);

    return 0;
}

// Función que se ejecuta al descargar el módulo (rmmod)
static void __exit modulo_sensor_exit(void) {
    // Liberar el pin asignado para que otros procesos lo usen
    gpio_free(GPIO_PIN_SENSOR);
    printk(KERN_INFO "[RPI5-LKM] Módulo removido y GPIO liberado. ¡Adiós Raspberry Pi 5!\n");
}

module_init(modulo_sensor_init);
module_exit(modulo_sensor_exit);

```

---

## Paso 4: Crear el Makefile de Compilación Cruzada

En la misma carpeta del módulo (`~/mi_modulo_rpi`), crea un archivo llamado `Makefile`.

Este archivo le indica a las herramientas de compilación que utilicen el árbol de código fuente del kernel que preparamos en el **Paso 2**.

```makefile
obj-m += modulo_sensor.o

# Ruta absoluta hacia las fuentes del kernel preparadas en el Host
KDIR ?= /home/TU_USUARIO/linux

all:
	make -C $(KDIR) M=$(PWD) modules

clean:
	make -C $(KDIR) M=$(PWD) clean

```

*(Asegúrate de cambiar `/home/TU_USUARIO/linux` por la ruta real donde clonaste el kernel en el paso 2).*

---

## Paso 5: Compilar en la máquina Linux (Host)

Ahora ejecuta la compilación desde tu carpeta `~/mi_modulo_rpi`. Debes pasar explícitamente los parámetros de arquitectura y compilador para que el Makefile actúe de manera cruzada:

```bash
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-

```

Si todo sale bien, verás un output de compilación y se generará un archivo binario ejecutable por el kernel con extensión **`.ko`** (**Kernel Object**): `modulo_sensor.ko`.

Puedes verificar que efectivamente se compiló para la Raspberry Pi y no para tu PC corriendo:

```bash
file modulo_sensor.ko

```

Debería responder algo similar a: *ELF 64-bit LSB relocatable, **ARM aarch64***.

---

## Paso 6: Transferir y probar en la Raspberry Pi 5

Dado que la Raspberry Pi no hará trabajo pesado, simplemente le enviaremos el binario final mediante `scp` (reemplaza con la IP y usuario de tu Pi):

```bash
scp modulo_sensor.ko usuario@111.111.1.111:/home/usuario/

```

### Ejecución en la Raspberry Pi 5:

Conéctate por SSH a tu Pi 5 e interactúa con tu nuevo módulo hecho a medida:

1. **Cargar el módulo:**
```bash
sudo insmod modulo_sensor.ko

```


2. **Verificar el mensaje impreso en el búfer del Kernel:**
```bash
sudo dmesg | tail -n 10

```


*Deberías ver las líneas:* `[RPI5-LKM] Inicializando el módulo...` y el estado del pin GPIO.
3. **Remover el módulo:**
```bash
sudo rmmod modulo_sensor

```


4. **Verificar la salida:**
```bash
sudo dmesg | tail -n 10

```


*Verás:* `[RPI5-LKM] Módulo removido y GPIO liberado. ¡Adiós Raspberry Pi 5!`
